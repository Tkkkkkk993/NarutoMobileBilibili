# 假人慢打编辑器

基于 **Godot 4.6 / GDScript** 的仿《火影忍者》手游格斗项目与实体编辑工具，面向角色制作、技能编排、连招演示和战斗机制研究。

项目将战斗框架与 Godot 编辑器插件放在同一工程中：通过可视化工具调整动画帧、受击框、攻击框和特效，再进入战斗场景验证效果。可以从现有角色入手修改，也可以结合 GDScript 扩展自己的角色与玩法。

目前仍在持续开发中，角色完成度、编辑工具和战斗表现以当前工程为准。

## 功能概览

### 实体与动画编辑

- **实体加载与切换**：加载实体场景，在多个已加载实体之间切换、重载。
- **逐帧数据编辑**：调整动画锚点、受击框位置、形状及显示状态。
- **攻击框编辑**：配置攻击框的动画绑定、逐帧位置与 XYZ 三轴范围，支持复制、粘贴、撤销和重做。
- **信息点与特效绑定**：编辑动画中的命名信息点，配置特效绑定数据。
- **图形化脚本**：提供积木模式与事件表模式，编排实体行为；也可使用 GDScript 扩展逻辑。
- **动画预览**：支持播放、逐帧查看、速度调整、缩放与拖拽，适配序列帧、AnimationPlayer 和组合渲染实体。
- **测试入口**：从编辑器启动当前角色的测试战斗，形成“编辑 → 保存 → 测试 → 调整”的制作流程。

### 战斗框架

- 平面移动与高度表现，攻击框、受击框及纵深判定。
- 普攻、技能、奥义、替身、秘卷与通灵相关逻辑。
- 动作位移、取消窗口、预输入缓冲与动作优先级。
- 击退、击飞、抓取、霸体、无敌与连击保护。
- 时间缩放、停帧及战斗音效、特效表现。
- 三人队伍、回合切换，以及血量和奥义点继承。
- 键盘操作、触屏摇杆与技能按钮，以及 AI 行为扩展接口。

具体技能效果由各实体的数据与脚本决定。

## 快速开始

### 环境准备

- 使用 [Godot 4.6 标准版](https://godotengine.org/download/)，项目脚本主要使用 GDScript。
- 工程采用 **Compatibility（GL Compatibility）** 渲染模式。
- 保留完整的 `assets/`、`addons/` 和 `bin/` 目录。`bin/` 中包含 Spine GDExtension 及平台库，不能只复制脚本运行。
- 首次打开需要等待 Godot 完成资源导入和脚本扫描。

工程已包含 Windows Desktop、Android 导出预设。导出前需安装对应版本的 Godot 导出模板，并按目标平台配置 SDK、签名和输出路径；预设的存在不代表各平台都已完成兼容性验证。

### 打开与运行

1. 下载完整项目并解压，或克隆到本地。
2. 在 Godot 项目管理器中点击“导入”，选择根目录的 `project.godot`。
3. 等待资源导入完成，在“项目 → 项目设置 → 插件”中确认 **EntityEditor** 已启用。
4. 按 **F5** 运行项目，默认入口为 `scenes/main_menu.tscn`。
5. 从主菜单进入选人界面，选满三个角色，并为三个位置配齐秘卷、选满通灵后点击“出战”。

当前选人流程会将所选阵容同时用于双方，地图由程序随机选择。

### 第一次编辑角色

1. 在 Godot 的“实体编辑器菜单”面板中点击“打开编辑器”。
2. 点击“加载实体”，输入一个已有角色的场景路径，例如：

   ```text
   res://assets/entities/神秘面具男/entity.tscn
   ```

3. 根据需要进入“编辑帧数据”“编辑攻击框”“编辑信息点”“绑定特效”或“图形化脚本”。
4. 保存修改，使用“预览动画”检查表现，再点击“测试”进入战斗。

当前测试入口按实体所在目录名识别角色，适合 `assets/entities/<角色目录>/entity.tscn` 这样的顶层角色结构；嵌套子实体应放在所属角色的技能流程中测试。测试模式的默认对手为神秘面具男。

## 默认操作

以下按键以 `project.godot` 的输入映射为准；角色是否响应还取决于控制类型、技能配置和当前状态。

| 操作 | P1 | P2 |
| --- | --- | --- |
| 移动 | W / A / S / D | 方向键 |
| 普通攻击 | K | 主键盘 1 |
| 技能一 | J | 主键盘 2 |
| 技能二 | I | 主键盘 3 |
| 技能三 / 奥义槽 | L | 主键盘 4 |
| 替身 | 空格 | 主键盘 5 |
| 秘卷 | P | 未绑定 |
| 通灵 | / | 未绑定 |
| 扩展技能槽 1 / 2 | 8 / 9 | 未绑定 |

可以在“项目 → 项目设置 → 输入映射”中修改。当前主键盘 `1` 还会切换调试显示总开关，与 P2 普攻存在按键重叠，双人调试时建议调整映射。

## 项目结构

```text
.
├── project.godot             # Godot 工程配置与输入映射
├── export_presets.cfg        # Windows / Android 导出预设
├── addons/
│   ├── entityeditor/        # 实体、帧数据、攻击框、特效及图形化脚本编辑器
│   └── virtual_joystick/    # 虚拟摇杆组件
├── assets/
│   ├── entities/            # 实体基类、角色、秘卷、通灵、子实体与配套数据
│   ├── audio/               # 音乐、语音与音效
│   ├── fonts/               # 字体
│   ├── stages/              # 场景素材
│   └── UI/                  # 界面素材
├── autoload/                # 队伍、对局、时间、音频、输入等全局管理
├── bin/                     # Spine GDExtension 与平台库
├── components/              # 攻击框管理等组件
├── data/                    # 角色、秘卷、通灵的选择列表
├── managers/                # 实体管理
├── scenes/                  # 主菜单、选人、战斗及 UI 场景
├── scripts/                 # 场景与界面脚本
├── script_templates/        # 脚本模板
├── shader/                  # 着色器
└── theme/                   # UI 主题
```

## 角色数据与扩展

一个实体通常由场景、脚本、动画资源和编辑器生成的数据组成。按实际需求使用以下文件，并非每个实体都必须具备全部文件：

| 文件 | 用途 |
| --- | --- |
| `entity.tscn` | 实体场景与节点结构 |
| `entity.gd` | 角色或实体的自定义逻辑 |
| `entity_frame_data.json` | 动画帧、锚点和受击框数据 |
| `attack_boxes.json` | 攻击框配置 |
| `info_points.json` | 动画信息点数据 |
| `effect_bindings.json` | 特效绑定数据 |
| `visual_script.json` | 积木与事件表脚本数据 |
| `portraits/` | 选人立绘与图标 |

新增角色时，建议参考已有实体，准备独立的目录、场景和资源，检查复制后的资源引用与脚本类名，再通过编辑器调整数据。需要出现在选择界面的内容，还需加入对应列表：

- `data/characters.json`：角色列表。
- `data/scrolls.json`：秘卷列表。
- `data/summons.json`：通灵列表。

列表中的 `name` 为显示名称，`id` 对应 `assets/entities/` 下的实体目录名。头像、场景和目录命名需与加载逻辑保持一致。

阅读或扩展代码时，可从以下入口开始：

- `assets/entities/entity_base.gd`：实体公共逻辑、战斗状态、输入与受击处理。
- `assets/entities/animated_sprite_2d_entity.gd`：序列帧实体实现。
- `assets/entities/animation_player_entity.gd`：AnimationPlayer 实体实现。
- `assets/entities/visual_script_component.gd`：图形化脚本运行逻辑。
- `autoload/match_config.gd`：对局配置、队伍与回合状态。
- `addons/entityeditor/`：编辑器工具实现。

## 常见问题

**找不到实体编辑器入口**  
确认 EntityEditor 插件已启用，并检查 Godot 输出面板是否有脚本加载错误。插件脚本修改后可尝试禁用再启用，或重启 Godot。

**提示 Spine 扩展或动态库加载失败**  
检查 `bin/spine_godot_extension.gdextension` 及当前系统、架构对应的库文件是否齐全，确认引擎与扩展版本兼容。扩展配置中列出的架构不一定都附带了二进制文件。

**编辑后测试效果没有变化**  
先确认对应编辑窗口中的数据已经保存，再重载实体或重新启动测试。不同工具会写入不同的数据文件。

**检查更新失败**  
插件启动时会根据 `addons/entityeditor/manifest.json` 检查在线更新。检查失败可先查看网络与服务状态；本地编辑入口不依赖更新成功。接受更新会覆盖清单中对应的项目文件，自定义修改建议先提交版本控制或备份。
